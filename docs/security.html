Security Policy for Superpower

Last updated: September 15, 2026

Security reports are important to the Superpower project. This policy explains which issues are most relevant, how to report them responsibly, and the trust boundaries users should understand when connecting Model Context Protocol (MCP) servers and third-party tools.

1. Security model

Superpower runs as a browser extension on supported AI web applications and communicates with MCP endpoints configured by the user. The extension can detect supported tool-call output, send user-requested tool calls to configured MCP servers, and insert returned results into the active conversation.

MCP servers and tools may have capabilities outside the browser. Users should therefore connect only to servers and tools they trust, protect credentials used by those services, and understand the effects of a tool before authorizing or automating execution.

2. Issues in scope

Examples of security issues that are especially useful to report include:

  • unauthorized execution of MCP tools or actions without the expected user workflow;
  • credential, token, API key, or secret exposure caused by Superpower;
  • cross-origin or message-passing weaknesses that allow an untrusted page to control extension behavior;
  • privilege or permission misuse by the extension;
  • injection vulnerabilities in Superpower-controlled UI or tool-result rendering;
  • unsafe handling of remote configuration that could cause code execution;
  • sensitive data being transmitted to an unexpected destination;
  • security-relevant dependency vulnerabilities that are exploitable through Superpower; and
  • other vulnerabilities that materially compromise confidentiality, integrity, or authorized tool execution.

3. Issues generally outside scope

Issues that exist only in a third-party AI website, MCP server, model provider, API, or external tool are normally outside the Superpower project's scope unless Superpower introduces or materially amplifies the vulnerability.

Reports based only on automated scanner output without a reproducible security impact, denial-of-service testing against third-party infrastructure, social engineering, and attempts to access data that is not your own are not appropriate security reports.

4. Reporting a vulnerability

Please do not publish credentials, private data, or actionable exploit details in a public GitHub issue.

For a potentially sensitive vulnerability, use the private publisher contact information provided in the Chrome Web Store listing. If private security reporting is available through the project's GitHub repository, that channel may also be used.

A useful report should include:

  • the affected Superpower version;
  • browser and operating system information;
  • the affected supported website or MCP transport, if relevant;
  • clear reproduction steps;
  • the expected and observed behavior;
  • the security impact;
  • a minimal proof of concept when safe to provide; and
  • any proposed mitigation or additional context.

Do not include live API keys, passwords, session cookies, private conversations, or other secrets in the report.

5. Coordinated disclosure

The project will make a reasonable effort to validate credible reports, determine whether the issue is within scope, develop an appropriate remediation, and coordinate disclosure when a vulnerability is confirmed. Public disclosure should avoid unnecessarily exposing users before a practical fix or mitigation is available.

6. Good-faith security research

Good-faith research should be limited to systems and data you are authorized to test. Avoid privacy violations, service disruption, destruction of data, persistence on third-party systems, or accessing information beyond what is necessary to demonstrate the issue.

7. MCP server and tool responsibility

Superpower does not operate or audit every MCP server or tool that a user may connect. Third-party MCP servers can define their own authentication, authorization, logging, data retention, and tool behavior. Users are responsible for evaluating those services before connecting them.

8. Security updates

Security-related fixes may be delivered through normal Superpower releases. Users should keep the extension and connected MCP software up to date and review release information when security-relevant changes are announced.

9. Related information

For information about data handling, see the Privacy Policy. For general help and non-sensitive bug reports, see Support.
