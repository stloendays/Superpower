# Browser Extension Operation Guide

This guide covers the normal Superpower browser workflow and a safe way to test local builds without publishing them to the Chrome Web Store.

## 1. Start an MCP server or proxy

Superpower is a browser MCP client. The browser extension does not launch local stdio commands directly, so local tools should be exposed through a browser-accessible MCP endpoint.

For the standard local Superpower setup, use:

```text
Transport: Streamable HTTP
Endpoint:  http://localhost:3006/mcp
```

Keep the local MCP proxy running while you use the extension.

## 2. Connect Superpower

1. Open a supported AI website such as ChatGPT.
2. Open the Superpower sidebar.
3. In **Connect MCP**, paste the MCP endpoint or a supported MCP JSON configuration.
4. Leave transport selection on automatic unless you are diagnosing a compatibility issue.
5. Click **Connect**.

For local setups, Superpower should automatically recognize `http://localhost:3006/mcp` as **Streamable HTTP**.

A successful connection should show **MCP ready** and the number of available tools.

## 3. Review tools and instructions

After connecting:

1. Open **Available Tools** and confirm the expected tools are present.
2. Open **Instructions** and review the generated MCP instructions.
3. Keep custom instructions focused on execution policy and user preferences. Tool schemas are generated by Superpower and do not need to be copied manually.

If you reloaded the extension while an AI page was already open, refresh that page once so the new content script is injected cleanly.

## 4. Run a safe first test

Start with a read-only task before trying state-changing operations. For example:

> List the files on my Desktop and summarize what is there. Do not modify, move, or delete anything.

The expected flow is:

```text
Web AI
  -> structured tool call
  -> Superpower
  -> MCP server / proxy
  -> local tool
  -> tool result
  -> same AI conversation
```

Check the tool call and returned result before moving on to write, delete, process-control, or system-configuration tasks.

## 5. State-changing tasks

For actions that can modify the machine or external systems:

- inspect the target first when its current state is unknown;
- prefer targeted changes over broad rewrites;
- review paths and arguments before execution;
- avoid retrying a state-changing call unless you know whether the previous attempt succeeded;
- use review-gated workflows for multi-step actions where possible.

## Test a local build without publishing

You do not need to upload every change to the Chrome Web Store while developing.

### Build

Requirements: Node.js 22.12+, pnpm 9.x, and a Chromium-based browser.

```bash
git clone https://github.com/stloendays/Superpower.git
cd Superpower
pnpm install
pnpm base-build
```

The production extension is built into `dist/`.

### Load the unpacked extension

1. Open `chrome://extensions/`.
2. Enable **Developer mode**.
3. Disable the Chrome Web Store copy of Superpower temporarily so only one Superpower instance is active.
4. Click **Load unpacked**.
5. Select the repository `dist/` directory containing `manifest.json`.
6. Open or refresh the AI website you want to test.

### After making another code change

1. Run `pnpm base-build` again.
2. Return to `chrome://extensions/`.
3. Click **Reload** on the unpacked Superpower extension.
4. Refresh all already-open AI website tabs.

This avoids extension-instance conflicts and stale content scripts during testing.

## Quick troubleshooting

### `SSE error: 404`

First confirm the saved endpoint and transport. For the standard local proxy they should be:

```text
http://localhost:3006/mcp
streamable-http
```

An error message containing the word `SSE` is not, by itself, enough to prove the selected transport is SSE. Check the actual saved configuration and request URL.

### Instructions stay on `Loading instructions...`

Reload the extension and refresh the AI page. Current builds share generated instruction state across content bundles, so a newly opened popover should reuse instructions already generated by the sidebar.

### Two different Superpower UIs or inconsistent state

Check `chrome://extensions/` and make sure the Web Store version and unpacked development version are not enabled at the same time.

### Local stdio configuration does not connect

A browser extension cannot directly spawn a local stdio MCP process. Run it through Superpower Host or another browser-accessible MCP proxy, then connect the extension to that endpoint.
